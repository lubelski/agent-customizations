# message-panels

Draws the Claude Code transcript in the style of `pi-customizations`' `assistant-background.ts`, `half-bleed.ts` and `recessed-tools.ts`. Everything here applies to the terminal surface only. Other surfaces draw Claude Code's own rows.

## What it changes

- **Assistant replies** draw as Markdown in a warm gray panel (`#2a2725`). The panel has no `⏺` bullet and no indent column.
- **Typed prompts** draw in a dark orange-brown panel (`#4a3226`) with warm off-white text (`#efe6df`). Other user-side rows keep Claude Code's drawing: task notifications, and messages from other agents or sessions.
- **Panel spacing.** The `fontCompat` option in `/config` picks one of two layouts. Each panel's fill is inset one cell from each side of the row, and the text has one cell of fill on each side.
  - Off (the default): half-height caps above and below the text (`▄` and `▀`, with quadrant corners `▗ ▖ ▝ ▘`) and half-block side edges (`▐`, `▌`) in place of whole rows. The caps are the whole spacing, so two panels leave one row between their fills, half from each cap. This needs a font that has Block Elements.
  - On: one row of fill above and below the text, and one blank row outside the panel. Every edge is a whole row or cell, so older terminals, mobile terminals and simple fonts draw it correctly.
- **Copying a panel.** A click on a panel's top-right cell copies the panel's text as written, with its Markdown and without the panel's glyphs. That cell is the `▖` corner of the top cap, or the last fill cell of the top padding row with `fontCompat` on. Each panel copies only its own text, so a reply split by tool calls copies one part at a time. A summary panel has no copy cell, since its text is the summary. Ctrl+o draws the full text, with its own copy cell.
- **Summary blocks.** In the normal view, Claude Code condenses text the model wrote between tool calls. Those blocks draw in the same panel as dim italic plain text, cut to 3 lines with `…`. Ctrl+o shows the full text.
- **Tool calls** draw as one dim line each: `› <tool> · <main input>`, such as `› Bash · git status`. MCP tools show their name without the `mcp__<server>__` prefix. A file path draws short: `pool-06 - src/a.ts` for a file in the Claude Code worktree `pool-06`, `src/a.ts` beneath the session's directory, and `~/notes.md` beneath the home directory. A path still too wide for the line drops directories from its middle and keeps its first segment and its file name: `pool-06 - src/…/ActivityLogTimeline/styles.module.css`. A call that errored or was interrupted keeps Claude Code's full row.
- **Tool output.** A call that succeeded shows no output. Ctrl+o shows everything.
- **Expanded tool rows.** In the ctrl+o view, under `--verbose`, and for a call that errored or was interrupted, the one-line label heads an indented block with one cell of margin on each side. The block lists the call's input as `key: value` lines, then its output: stdout and stderr for Bash, numbered content for Read, a colored patch for Edit and Write, text blocks for a plugin tool, and JSON for anything else. The input shows 8 lines and the output 12. A `▸ n more lines` button beneath reveals the rest, and `▴ less` folds it again. Which rows are revealed is kept in `$.state`, so a reload keeps them. A click on a tool row also expands it, and Claude Code paints that row's container in the `userMessageBackgroundHover` theme color across the full width. The block covers that paint with cells in the terminal's own background: its Box names a background string the painter does not style, so the fill is written unstyled.
- **Slash commands.** A command's echo draws as one dim line, `› /model`, whatever origin the engine stamped it with. The command's output draws dim beneath it, indented, and an error line draws in the error color.

## Spacing

A group of calls with a failed one draws as the mod's own lines, the failed one in the error color. A group the engine summarizes for another reason (recalled memory, hook timing) keeps the engine's line, pulled up over its blank row with a top margin of -1. With `fontCompat` on, a panel has one blank row of the terminal's background below it, and one above it unless the row before it is another panel. Two panels in a row therefore share one blank row, and a tool line sits one blank row from a panel above or below it. A tool line and a slash command's echo take no blank row of their own. The mod knows the row before a panel from the order rows are stored in, so panels that `--resume` loads take a blank row above even after another panel. The line that closes a turn, `Worked for 5s · done 5:27 PM`, is drawn by the mod: dim, with a `·` in the column where a tool line has its `›`, so its text aligns with a tool line's, and no blank row above it. The engine's props give the word and the duration. The clock is stamped on the line's first draw and kept for redraws. A line that waits on background agents stays the engine's. Other engine rows, such as mod notices, keep their blank row.

## Working with other mods

The assistant panel wraps whatever a mod beneath it drew for `AssistantMessage`. If the tree beneath holds Claude Code's own row, the mod draws Markdown from `e.props.text` instead. This lets `code-brackets` supply the panel's body in either chain order.
